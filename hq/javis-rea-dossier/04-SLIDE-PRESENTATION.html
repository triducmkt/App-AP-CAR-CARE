SLIDE 03 // DOCKER & VPS DEPLOYMENT ANATOMY

Giải Phẫu Kiến Trúc Docker & VPS Của Javis OS

Phân tích từ Dockerfile & docker-compose.yml: Tách biệt 100% Code tĩnh và Dữ liệu sống

📦 Cấu Trúc Multi-Stage Container & 4 Volumes

  • Hybrid Image (Python 3.12 + Node 22.23.4): Ghép binary Node.js từ image chuẩn vào Debian Bookworm Python, cài sẵn tini (PID 1), ffmpeg, ripgrep, Chromium deps, Claude CLI & Codex CLI.
  • Bảo mật User javis (UID 10001): Mã nguồn trong /app là bất biến (immutable). Cập nhật phiên bản mới chỉ thay /app, giữ nguyên 4 ổ đĩa (Volumes):
    1. javis-data:/data (SQLite, Token OAuth, Phiên Zalo QR).
    2. javis-brains:/brains (Kho tài liệu Markdown).
    3. claude-auth & 4. codex-auth (Giữ đăng nhập AI).
  • Đa khách hàng trên 1 VPS: Đổi JAVIS_NAME & JAVIS_HOST_PORT (7777, 7778...) để chạy nhiều thực thể độc lập kèm Cloudflare Tunnel & Watchtower tự cập nhật.

SLIDE 04 // DEEP DIVE: SERVER/MCP_HUB.PY (2.290 DÒNG CODE)

Bí Mật Cổng Đấu Nối Trung Tâm: Javis MCP Hub

Làm thế nào Javis gom 29+ dịch vụ vào 1 cổng POST /hub/mcp duy nhất mà không làm tràn bộ nhớ AI?

🛡️ 1. Khóa Quyền Cứng 3 Mức (_guard)

Chặn ở tầng Code Python — Không phụ thuộc Prompt
  • Chỉ đọc (readonly): Chỉ mở các hàm tra cứu (read). Ẩn và chặn hoàn toàn lệnh sửa/xóa.
  • Ghi nháp (safe): Cho phép tạo bản nháp (Draft Gmail, ghi chú), nhưng chặn cứng các hành động đụng tới tiền, tạo đơn hàng thật hoặc gửi tin nhắn cho khách.
  • Toàn quyền (full): Mở toàn bộ công cụ (danger), nhưng vẫn bị kiểm soát bởi bộ đếm rate_limit (vd Zalo tối đa 20 lệnh/phút).

⚡ 2. Lazy Tool Search (Tiết kiệm 85% Token)

Giải quyết bài toán >100 Tools
  • Khi bật nhiều kết nối, nếu nạp toàn bộ 100+ schema vào prompt sẽ làm AI chậm và tốn hàng chục nghìn token mỗi câu chat.
  • Hub tự động giấu toàn bộ tool vào pool và chỉ đưa cho AI 2 công cụ siêu nhẹ:
    • javis_search_tools(query)
    • javis_run_tool(name, args)
  • AI cần làm việc gì mới tìm đúng 3 tool liên quan nhất để nạp schema chi tiết!

🔍 3. Xử Lý Tool "2 Trong 1" (arg_rules)

Kiểm tra sâu tới từng Tham số
  • Nhiều dịch vụ như Pancake POS hoặc Composio gộp cả đọc lẫn ghi vào chung 1 tool (phân biệt qua tham số action="list" vs action="create").
  • Khi liệt kê (tools/list), Hub đánh dấu multiplexed=True để AI vẫn nhìn thấy tool ở chế độ Chỉ đọc.
  • Khi thực thi (tools/call), hàm mcp_catalog.allowed() soi trực tiếp args["action"] để chặn ngay nếu cố tình tạo đơn!

💬 2. Giải Phẫu Fanpage & Messenger Bot (messenger_bot.py)

  • Tách Token Riêng Từng Fanpage (_resolve_page): Dùng User Token gọi GET /me/accounts để lấy access_token riêng của từng Fanpage (ẩn token khỏi kết quả trả về cho AI để chống lộ khóa).

  • Bảo mật Webhook & Cửa sổ 24h: Kiểm tra chữ ký X-Hub-Signature-256 (HMAC-SHA256), tự động chuyển Markdown sang chữ thuần và cắt tin ở mốc 1.900 ký tự.

SLIDE 07 // B2B SINGLE-TENANT REPLICATION STRATEGY

Chiến Lược Nhân Bản SME OS Cho Khách Hàng B2B Qua GitHub

Mỗi doanh nghiệp B2B sở hữu 1 bản cài đặt độc lập (Single-Tenant) từ kho GitHub Master của anh Đức

🏆 5 Lợi Thế Tuyệt Đối Của Mô Hình "1 Công Ty = 1 Bản Độc Lập"

  • 1. Chi phí Server cho anh Đức = \$0: Mỗi công ty khách hàng chạy trên chính Google Workspace / Gmail miễn phí của họ (Google Sheets + Apps Script + Drive 15GB + GitHub Pages).
  • 2. Cô lập Dữ liệu Tuyệt đối 100%: Doanh thu, bảng lương, danh sách khách hàng của Công ty A nằm trong Google Sheet riêng của Công ty A — không bao giờ rò rỉ chéo sang Công ty B.
  • 3. Vũ khí Chốt Sale Tư vấn B2B: Khách hàng nắm trọn quyền sở hữu trên Google Drive của họ, xóa bỏ hoàn toàn nỗi sợ "hết hợp đồng bị thu hồi phần mềm".
  • 4. Cá nhân hóa White-Label trong 30 giây: Đổi Logo, Tên công ty, Màu thương hiệu, Chi nhánh ngay trong bảng System_Settings mà không phải sửa code.
  • 5. Đồng bộ tính năng mới tự động: Anh Đức và Lucy chỉ phát triển trên 1 repo gốc sme-os-master-template, dùng GitHub Actions / Clasp đẩy bản cập nhật xuống các khách hàng.
